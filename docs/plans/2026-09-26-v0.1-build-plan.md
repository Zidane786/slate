# Slate v0.1 build plan

Implements `docs/specs/2026-09-26-slate-design.md` (the spec wins on any conflict). Three
parallel workstreams share the contracts below; the controller integrates and runs the E2E.

Terms: **batch file** = JSON Claude writes listing new tickets for `add`; **preview** = `kanban/preview.json`, shown on the board, never saved; **draft** = a saved ticket with status `draft`, not ready to work.

Version for everything in this release: **`0.1.0`**, schema version **`1`**.

## Workstreams

| WS | Owns | Files |

Each workstream touches only its own files.

## Contract 1: `tickets.json`

```json
{
  "meta": {
    "project": "Acme", "prefix": "ACME",
    "slate_version": "0.1.0", "schema_version": 1,
    "generated": "2026-09-26",
    "statuses": ["draft", "backlog", "ready", "in_progress", "review", "user_testing", "done"],
    "areas": ["backend", "frontend", "infra"],
    "priorities": ["P0", "P1", "P2", "P3"],
    "user_test_areas": ["frontend", "ui"]
  },
  "phases": [{ "id": "P1", "name": "Link arrives", "goal": "…", "demo": "…" }],
  "tickets": [{
    "id": "ACME-001", "title": "…", "summary": "…", "story": "…", "visual": "markdown, optional",
    "description": "markdown", "acceptance": ["…"], "test_scenarios": ["When …, then …"],
    "user_tests": [{ "title": "…", "setup": "…", "steps": ["…"], "expect": "…", "required": true }],
    "technical": "markdown, optional", "plan_doc": "docs/plans/…md, optional",
    "phase": "P1", "areas": ["frontend"], "priority": "P1", "rank": 1, "status": "backlog",
    "depends_on": [], "unlocks": [], "estimate": "1d", "labels": [],
    "handoff": [{ "date": "2026-09-26", "status": "review", "note": "…" }],
    "user_checks": { "0": { "result": "pass", "date": "2026-09-26", "note": "" } }
  }]
}
```

- Required on every ticket: `id title phase priority rank status depends_on areas estimate`
  plus `summary story description acceptance test_scenarios`.
- **Legacy ticket** = has neither `summary` nor `story` (Forge-style). Missing new fields on a
  legacy ticket are **warnings**; on any other ticket they are **errors**. Tickets created by
  `new`/`add` are always validated strictly.
- `user_tests` required (at least one with `required: true`) when any of the ticket's `areas`
  is in `meta.user_test_areas` — error for non-legacy tickets.
- **Draft tickets** (status `draft`): saved on the board but not finished. Only `title`,
  `summary`, `phase` are required; every other rule is skipped for them. `next`/`list` never
  pick them; they don't count as ready. Leaving `draft` (to any status) runs the full strict
  validation on that ticket first and refuses with the list of what's missing. Other tickets
  may not depend on a draft unless they are drafts themselves (error).
- Open statuses (resume first): `in_progress`, `review`, `user_testing`.
- Ready: status `backlog` or `ready` and every dependency `done`.

## Contract 2: `board.py` CLI

Python 3.9+ stdlib only. `tickets.json` lives next to `board.py` (`Path(__file__).parent`).
Header lines exactly:

```python
#!/usr/bin/env python3
# Slate board v0.1.0 — generated by the Slate plugin; do not edit, run /slate:upgrade
SLATE_VERSION = "0.1.0"
SCHEMA_VERSION = 1
```

Exit codes: `0` ok, `1` validation error or refused action, `2` usage error. Errors go to
stderr, each naming ticket id + field. Every write: validate whole board → write temp file in
the same dir → `os.replace`. JSON: `indent=2, ensure_ascii=False`, trailing newline, key order
preserved. Any write command first runs `check`; if the board on disk is invalid, it refuses.
If `meta.schema_version` > `SCHEMA_VERSION` → every write refuses with
"board is newer than this board.py; update the Slate plugin".

| Command | Behaviour |
|---|---|
| `init --project NAME --prefix PFX [--areas a,b,c]` | Create tickets.json per Contract 1 with empty phases/tickets. Prefix `^[A-Z][A-Z0-9]{1,9}$`. Refuse if file exists. |
| `version [--against PLUGIN_ROOT] [--json]` | Print `board 0.1.0 · schema 1 · tickets.json 0.1.0/1`. With `--against`, read `PLUGIN_ROOT/.claude-plugin/plugin.json` `version` and print one of `same`, `behind` (board older than plugin), `ahead`. JSON: `{board, schema, file_slate_version, file_schema_version, plugin, relation}`. |
| `next [--brief] [--json] [--against PLUGIN_ROOT]` | Open tickets first, else lowest-rank ready. `--brief`: one line `Slate 0.1.0: ACME-014 in review · 2 waiting for you to test · next ready ACME-016` (+ ` · board behind plugin, run /slate:upgrade` when `--against` says behind). Prints nothing and exits 0 if tickets.json missing. |
| `list [N] [--json]` | Next N ready tickets (default 5). |
| `show ID [--json]` | Plain-text sections in board drawer order: summary, story, picture, done when, try it yourself (+ recorded result), automated tests, details, technical, needs/unlocks, plan doc, history. |
| `status [--json]` | Per-phase done/total, count per status, list of `user_testing` tickets. |
| `check [--json]` | Validate (spec §6.2). Print errors then warnings; exit 1 if errors. |
| `new --title … --summary … --phase … [--draft] [--story …] [--description …] [--acceptance … (repeatable)] [--test … (repeatable)] [--priority P2] [--areas a,b] [--depends ID,…] [--estimate 1d] [--visual …] [--technical …] [--user-test-json '{…}'] (repeatable) [--after ID] [--dry-run]` | Create one ticket; next free id; rank = end, or right after `--after`. Status `backlog` (strict: story/description/acceptance/test required) or `draft` with `--draft` (relaxed). |
| `add --file BATCH [--after ID] [--dry-run] [--as-draft]` | Batch file = `{phases?: [...], tickets: [{key, ...fields w/o id/rank/status/unlocks}]}`. `depends_on` may hold batch keys or existing ids. Assign ids in batch order, ranks appended at end (or inserted after `--after`), recompute `unlocks` for all tickets, status `backlog`, validate strictly. `--as-draft`: status `draft`, relaxed validation. `--dry-run`: write `kanban/preview.json` = `{"preview": true, "phases": [...new], "tickets": [...resolved new tickets with ids/ranks]}` and print ids/ranks table; real run deletes `preview.json` on success. |
| `batch-check --file BATCH` | Validate a batch file alone: required fields, keys unique, deps resolvable, writing rules (title ≤ 80 chars; acceptance non-empty; test scenario without "when" → warning; user-test-area rule). |
| `discard-preview` | Remove `kanban/preview.json` if present. |
| `set ID STATUS [--handoff "…"]` | Status must be in meta. `--handoff` required for `review`, `user_testing`, `done` (appends `{date,status,note}`). `in_progress`/`review`/`user_testing`/`done` refuse if deps not done. `user_testing` refuses if ticket has no user_tests. `done` refuses if any required user test lacks a `pass` in `user_checks`, if no commit is linked (in a git repo; shas verified), or if the repo has a remote and no PR is linked; `--no-code "why"` / `--no-pr "why"` override and are recorded in `done_without`. Every refusal prints `fix:` lines. |
| `edit ID key=value … [--file PATCH.json]` | `key=value` sets a string; `key:=JSON` sets parsed JSON. Refuse `id rank status handoff user_checks unlocks` (use the dedicated commands). Recompute `unlocks` when `depends_on` changes. |
| `rerank ID --after OTHER` (or `--first`) | Move in rank order, reassign ranks 1..n contiguous in the new order, validate (deps must stay earlier). |
| `promote ID` | Shortcut for `set ID backlog` from `draft` (strict validation, prints what is missing on refusal). |
| `add-phase --id P3 --name … --goal … --demo …` | Append a phase; refuse duplicate id. |
| `usertest ID INDEX pass\|fail [--note "…"]` | Record `user_checks[str(INDEX)]`; INDEX must exist. A `fail` on a ticket in `user_testing` moves it to `in_progress` and appends a handoff note `User test failed: <title>: <note>`. |
| `link ID [--commit SHA\|REF …] [--message …] [--pr URL] [--pr-state …] [--pr-title …]` | Record commits (full sha, subject, branch, date via git) and the PR. Idempotent. Added after the first pass. |
| `set-meta key=value \| key:=JSON` | Allowed keys: project, repo_url, areas, user_test_areas. |
| `upgrade --from ASSETS_DIR` | Copy `index.html`, `board.py`, `README.md` from ASSETS_DIR into this dir, then run `python3 <new board.py> migrate` in a subprocess and pass through its output. |
| `migrate` | Apply schema migrations from `meta.schema_version` up to `SCHEMA_VERSION` (v1: add missing `schema_version`, `slate_version`, `user_test_areas`, append `user_testing` to statuses before `done` if missing). Always set `meta.slate_version = SLATE_VERSION`. Additive only. Then `check`. |

## Contract 3: `index.html`

Start from `../forge/kanban/index.html` (copy, then change). Keep single file, no deps, both
views, filters, overlay, export. Changes, per spec §5:

1. `<meta name="slate-version" content="0.1.0">`; footer text `Slate v0.1.0`; no "Forge" anywhere.
2. Title/brand from `meta.project` (fallback "Slate board").
3. Storage keys `slate.<prefix>.overlay.v1` and `slate.theme` (prefix from meta, fallback `board`).
4. Drawer order: Summary, Story, Picture (`visual`), Done when (checklist), Try it yourself
   (each user test: title, setup, numbered steps, expected; Pass/Fail buttons saved in overlay
   as `usertest:<i>`; recorded `user_checks` from the file shown as a badge), Automated tests
   (checklist), Details (`description`), Technical notes (`<details>` collapsed), Needs /
   Unlocks chips, Plan doc (path shown as code), History (handoff timeline, newest last).
   Legacy tickets (no summary/story) render as today: description first.
5. Markdown: add tables (`|a|b|` with separator row), blockquotes, `###` headings; fenced
   blocks `white-space: pre; overflow-x: auto`, never wrap.
6. `draft` column label "Draft" (cards muted, "not ready" tag); `user_testing` column label "User testing"; cards in it get a "needs you" badge.
7. Card shows `summary` under the title (one line, ellipsis).
8. Preview: after loading `tickets.json`, try `fetch("./preview.json")`; if it returns
   `{preview: true, ...}`, merge its phases/tickets for display only: dashed border + "preview"
   tag, never in export, never in overlay counts. A banner "Preview: N tickets not yet
   saved" shows at the top.
9. File-picker fallback still works when opened from `file://`.

## Contract 4: skills and hooks

- Skills: `init`, `plan`, `work`, `review`, `status`, `upgrade` (`plugins/slate/skills/<name>/SKILL.md`).
  `init` and `upgrade` have `disable-model-invocation: true`.
- Plugin root from a skill: the skill's base directory is `<root>/skills/<name>`, so root is
  `<base>/../..`; assets at `<root>/assets/board/`, templates at `<root>/templates/`.
- Every skill's step 0: `python3 kanban/board.py version --against <root>` → behind: offer
  `/slate:upgrade`, continue; ahead: read-only, tell user to update the plugin; missing
  `kanban/`: suggest `/slate:init` (except init itself).
- Hooks (`hooks/hooks.json`, `${CLAUDE_PLUGIN_ROOT}`):
  - SessionStart: `[ -f kanban/board.py ] && python3 kanban/board.py next --brief --against "${CLAUDE_PLUGIN_ROOT}" || true`
  - PreToolUse matcher `Edit|Write|MultiEdit|NotebookEdit`: `python3 "${CLAUDE_PLUGIN_ROOT}/hooks/guard_tickets.py"`
    reads the hook JSON on stdin; if `tool_input.file_path` resolves to a path ending in
    `kanban/tickets.json` → print "Change tickets through kanban/board.py (new, add, edit,
    set, rerank, usertest)." to stderr, exit 2. Otherwise exit 0. Never crash on bad input
    (exit 0).
