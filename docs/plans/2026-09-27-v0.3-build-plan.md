# Slate v0.3 build plan

Version **0.3.0**, board schema **3**, released 2026-09-27 (PR #8). Backwards compatible: schema 2
boards load, and `migrate` (or `/slate:upgrade`) moves them to 3 by adding only.

*Written after the release, from PR #8, the 0.3.0 CHANGELOG and the code as shipped, so the
build plans stay complete. It records the contracts 0.3.0 holds to; it was not the working plan.*

Existing contracts in `2026-09-26-v0.1-build-plan.md` and `2026-09-26-v0.2-build-plan.md` still
hold unless changed here. Every new error/refusal keeps the `error: <ID> <field>: …` +
`fix: <command>` / `ask the user: …` shape. Every write still validates the whole board, takes
the write lock and writes atomically.

## Goal

1. A built-in **Cancelled** state for work the team decided not to do. It never counts as done
   and doesn't block the tickets that depend on it.
2. **Per-state behaviours** that any state can have, so a team can add its own states (Won't fix,
   Duplicate, On hold) that behave exactly as it wants. Done and Cancelled are just states with
   these behaviours switched on.

## Schema 3 (additive; schema 2 boards stay valid)

- New role **`cancelled`**. New boards get 9 states: `draft backlog ready in_progress review
  user_testing merge_ready done cancelled`, label "Cancelled".
- `meta.status_flags`: `{ "<status>": { "<flag>": value } }`. Flags and what each role gets by
  default (`role_flags`); a flag set here overrides the role default:

  | Flag | Meaning | Default on |
  |---|---|---|
  | `resolves_deps` (bool) | A dependency in this state counts as resolved | done, cancelled |
  | `from_any` (bool) | Reachable from any state; workflow and dependency rules don't apply | cancelled |
  | `progress` (`done`\|`excluded`\|`open`) | How it counts in phase progress | done → `done`, cancelled → `excluded`, others `open` |
  | `terminal` (bool) | Finished: `next`, `list` and `/slate:work` never pick it | done, cancelled |
  | `notify_dependents` (bool) | Entering it writes a note on every dependent | cancelled |
  | `folded` (bool) | The board page folds its column by default | cancelled |

  Invalid flag names or values are ignored at read time and reported by `check`.
- Ticket fields (board.py-owned, refused in `edit` and batch files with a fix line):
  - `cancelled_from`: the state the ticket was in when cancelled; `uncancel` goes back there.
  - `dep_exceptions`: `{ "<DEP_ID>": "why" }`, dependencies the user agreed to keep past
    (`uncancel --keep-dependents`). Every dependency rule treats them as resolved.

## board.py

1. `cancel ID[,ID…] --reason "why"`: allowed from any state (no workflow or dependency rule
   applies). Reason required, or `NeedsHandoff` with the fix. Sets `cancelled_from`, adds the
   reason to the history, and writes a note on each dependent: "depended on ACME-046, Cancelled:
   <reason>". The dependency link stays. Several ids are all or nothing. Respects claims
   (`--as`, `--take-over`).
2. `uncancel ID --handoff "why" [--to STATUS] [--keep-dependents]`: back to `cancelled_from` (or
   `--to`) and notes each dependent. If a dependent already finished while it was cancelled,
   refuse with `ask the user:`; `--keep-dependents` keeps them as they are and records the
   reason in their `dep_exceptions`.
3. `edit-status NAME flag=value …` for the six flags. `add-status NAME --like OTHER` copies
   OTHER's role and its effective flags (only those that differ from the role are stored).
   Example: `add-status wontfix --after done --like cancelled --label "Won't fix"`.
4. Dependency checks, `next`, `list`, `status` and progress all read the flags, never the
   status name. Progress: `P1 Reset 3/15 done · 1 cancelled` (excluded states are left out of
   the total).
5. Serve API: `POST /api/cancel` and `POST /api/uncancel` (`keep_dependents` must be a bool), with
   the same checks as the CLI.
6. `migrate` 2 → 3 (`migrate_cancelled`): adds `cancelled` right after the done-role state. A
   status already named `cancelled` with role draft (or none) becomes the built-in cancelled role
   and moves after done. One with another role keeps it, and the change list prints the
   `add-status … --like cancelled` fix.

## Board page (`index.html`)

- Cancelled column after Done, folded by default (any `folded` state is).
- Cancelled cards are muted and struck through.
- Live mode: "Cancel ticket…" (asks for the reason) and "Undo cancel" in the drawer; dragging a
  card to Cancelled asks for the reason.
- States and their behaviours are never set up from the page: only from the CLI, or by the
  agent after showing the user and asking.

## Skills, templates, docs

- `/slate:plan`: "Cancel, remove or restore" section. Cancel is preferred once work started or
  when other tickets depend on the ticket; ask first and name the dependents.
- `/slate:work`, `/slate:status`, `/slate:sync`: cancelled tickets are finished; status shows
  "· N cancelled"; sync explains `cancelled_from` and `dep_exceptions` differences.
- `templates/SLATE.md` `## Workflow` lists each state's behaviours; `/slate:upgrade` offers to
  regenerate it (`workflow --markdown`).
- `reference/commands.md`, board `README.md`, root README, `TEST.md`, CHANGELOG 0.3.0,
  `upgrades/0.3.0.md`.

## Tests

`tests/test_cancelled.py` (cancel/uncancel, dependents, undo, bulk, API, migrate 2 → 3),
`tests/test_state_flags.py` (each flag, overrides, `--like`, `check` on bad flags), updates to
the board, merge, status and deps suites, `test_index_static.py` for the page, and the
`board-demo` fixture with cancelled tickets.
