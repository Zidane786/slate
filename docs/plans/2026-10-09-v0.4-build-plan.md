# Slate v0.4 build plan

Version **0.4.0**, board schema **3** (unchanged), released 2026-10-09 (PR #9).

*Written after the release, from PR #9, its commits, the 0.4.0 CHANGELOG and the code as
shipped, so the build plans stay complete. It records the contracts 0.4.0 holds to; it was not
the working plan. The design is spec decision 24 and §8.2.*

Existing contracts in the v0.1–v0.3 build plans still hold. Claude Code's behaviour does not
change: refusals still exit 2 with the reason on stderr, and the session-start line is still
plain text.

## Goal

**GitHub Copilot CLI support in the same plugin.** Copilot CLI loads the existing
`.claude-plugin/` manifest, the skills (`/slate:init`, `/slate:plan`, …) and the Claude-format
`hooks.json`. No second plugin folder; both tools share one board. The guard must hold in every
Copilot mode, including Autopilot with Allow all.

**Not in scope:** VS Code Copilot Chat. Its local agent ignores matchers and uses other tool
names, and half-support is worse than none.

## What Copilot CLI does differently (measured in 1.0.94) and the contract for each

| Copilot CLI does | Contract |
|---|---|
| The edit tool sends apply_patch text (`*** Update File: …`); one patch can touch several files | The guard reads every `Update File:`, `Add File:`, `Delete File:` and `Move to:` path and checks each like a `file_path`. |
| An exit-2 refusal reaches the model only as "hook exited with code 2" | Under Copilot (`COPILOT_CLI` set, patch text, or Copilot's camelCase input) the guard exits 0 with JSON `permissionDecision: "deny"` and the reason, flat and in `hookSpecificOutput`. |
| No `permission_mode`; the "ask" card shows in every mode, even Autopilot + Allow all; `-p` refuses "ask" | A missing mode means ask, as before. One unlock = one edit still holds. |
| PostToolUse sends `tool_result`, not `tool_response` | The activation hook reads neither; its note also goes out flat (`additionalContext`). |
| Plain SessionStart stdout is ignored | `session_start.py` prints `{"additionalContext": "…"}` when `COPILOT_CLI` is set. |
| Sets `COPILOT_CLI=1` for hooks and the agent's shell | `board.py unlock` names Copilot CLI's permission card instead of Claude Code's. |
| Runs hooks through PowerShell on Windows (`powershell` key) | Every hook in `hooks.json` has a `powershell` command that runs the new `hooks/run.cmd`, which finds `py -3`, `python` or `python3`. With none, it exits 0, because Copilot treats a failing preToolUse hook as a deny. |
| Has a PowerShell tool | Matchers include `PowerShell`. The guard blocks `Set-Content`, `Out-File`, `Copy-Item`, `Remove-Item`, `[IO.File]::WriteAllText` and the like on `tickets.json` (Claude Code's PowerShell tool benefits too). |

Copilot only runs its own hook events; Slate uses SessionStart, PreToolUse and PostToolUse,
which both tools have. Skills keep their plugin prefix, so they don't clash with Copilot's own
`/plan` and `/review`.

## Files

- `hooks/guard_tickets.py`: patch parsing, Copilot detection and JSON deny, PowerShell cmdlets.
- `hooks/session_start.py`: `additionalContext` output under Copilot.
- `hooks/hooks.json`: a `powershell` command per hook; `PowerShell` in matchers.
- `hooks/run.cmd` (new): the Windows launcher. `.gitattributes` keeps it CRLF.
- `board.py`: `unlock` text names the tool in use.
- Skills: name both tools where steps differ ("filled in by Claude Code or Copilot CLI"), look
  for `kanban/board.py` in the project rather than the plugin folder, and give Copilot's update
  commands (`copilot plugin update slate@slate`, then `/restart`) next to Claude Code's.
- `scripts/release_notes.py`: the release notes' install block includes Copilot CLI.
- Docs: `reference/commands.md`, both READMEs, board `README.md`, `templates/SLATE.md`,
  `TEST.md` level 5 (Copilot CLI live), spec decision 24 and §8.2, `CLAUDE.md` / `AGENTS.md`,
  CHANGELOG 0.4.0, `upgrades/0.4.0.md` (offers to replace the old "Copilot CLI support: planned"
  line in a project's `SLATE.md`).

## Tests

`tests/test_copilot.py` pins every row of the table above: patch paths (single and several
files), JSON deny under Copilot and exit 2 under Claude Code, session-start output, the
`unlock` text, the `powershell` command on every hook, PowerShell cmdlets in the guard, and the
`run.cmd` launcher (Windows-only tests run on the Windows CI jobs). `tests/conftest.py` clears
`COPILOT_CLI` so the rest of the suite runs as Claude Code.

## Verification (as recorded in PR #9)

- Full suite on Python 3.13 and 3.9: 955 passed, 4 skipped (the Windows-only tests); CI 6 checks
  green, Windows included.
- `claude plugin validate --strict` for the repo and the plugin; version guard 0.3.0 → 0.4.0.
- Live in Copilot CLI 1.0.94 on macOS (tmux, working copy): the session line reaches the model;
  `/slate:*` commands are listed; a direct edit is blocked with the reason; in Autopilot + Allow
  all the unlock shows the card, Yes allows one edit and the next is blocked; `copilot -p`
  refuses the unlock.
- Live in Claude Code with the 0.4.0 working copy: unchanged (edit blocked; unlock card, one
  edit, then blocked).
