## Board of record (branches and worktrees)
The board of record is `kanban/tickets.json` on the default branch in the main checkout. Every
branch and git worktree has its own copy of the file, so boards drift apart when several agents
or branches work at once.
- board.py warns (not fatal) when you write in a secondary worktree, when `SLATE_BOARD_OF_RECORD`
  (an environment variable naming the board of record's tickets.json) points at another file, or
  when the default branch's board has tickets or notes this one lacks. Take the warning
  seriously: stop and ask before writing more.
- See the difference: `python3 kanban/board.py diff main` (a branch, a path, or a folder).
- Bring changes across: `python3 kanban/board.py sync --from main --dry-run`, then without
  `--dry-run`. `copy-to PATH` writes a checked copy to another checkout.
- Git merges of tickets.json use the Slate merge driver (`python3 kanban/board.py
  install-merge-driver`, once per clone); it merges ticket by ticket and reports real conflicts.
- Parallel board.py commands are safe (they take turns through `kanban/.slate-write.lock`; a busy
  board means wait and retry). If a crashed command left the lock behind (older than 60 s, or
  its process is gone), `python3 kanban/board.py unlock-write` removes it.
- Who is on what: `set ID in_progress` claims the ticket for the current branch (create the
  branch first; `--as NAME` to override). `next` and `list` skip tickets claimed by someone
  else ("on: <name>"); touching one needs the user's OK and `--take-over "reason"`. `claim ID` /
  `release ID` do it by hand; `sync` and the merge driver keep the later claim.
- Sorting boards out (differences, merge conflicts, repairs) is `/slate:sync`.

## Bugs
A bug found in other work becomes its own ticket:
`python3 kanban/board.py new --bug --fixes {{PREFIX}}-004 --title "…" …`. It gets the labels
`bug` and `fixes-{{PREFIX}}-004`, ranks just before the ticket it fixes, and that ticket waits
for it. If the fixed ticket is already done or waiting for merge, board.py asks first
(`--reopen` moves it back to in progress, only with the user's OK).

## Unscheduled phases
Someday ideas live in a phase added with `add-phase … --unscheduled` (for example `BACKLOG`).
`next`, `list` and `/slate:work` skip its tickets; the board shows it last and folded. To build
one, move it first: `python3 kanban/board.py edit ID phase=P2`.

## Ticks, merges and unlocks
- Each "Done when" and "Automated tests" item is ticked on the board as it is proven:
  `python3 kanban/board.py check-item ID acceptance 0 --evidence "test name or what you saw"`.
- After review, user tests and a linked commit/PR, a ticket goes to `merge_ready` (Waiting for
  merge). It becomes `done` only when the user says the PR is merged
  (`link ID --pr-state merged`), or agrees to close it without one (`--no-pr "why"`).
- A broken board is repaired with the `fix:` lines `python3 kanban/board.py check` prints: a write
  that removes errors and adds none is accepted ("repair: N errors left").
- Hand edits to `kanban/tickets.json` are blocked. If one is truly needed (for example git conflict
  markers), explain why to the user, then run exactly
  `python3 kanban/board.py unlock --reason "…" --minutes 5`. Claude Code shows its approval card in
  Manual, Accept edits and Auto mode (the user's Yes on the card is the approval); in Plan,
  Bypass permissions and Don't-ask mode it is refused, and the user runs `unlock` in their own
  terminal (or tmux pane) and types the 4-letter code it shows. One unlock = one edit;
  if the user declines, stop. Every step is logged in `meta.unlock_log`. Copilot CLI support: planned.
- Board changes without hand edits: `note ID "…"` (a history note), `unlink ID --commit SHA` /
  `--pr` (wrongly linked code), `usertest ID N reset` (a wrongly recorded result), `remove ID
  --reason "…"` / `restore ID` (archive, ask first), `edit ID1,ID2 key=value` (several at once).
  Every command: `<plugin>/reference/commands.md`, or `python3 kanban/board.py <command> --help`.
- `kanban/.slate-unlock*.json`, `kanban/.slate-write.lock`, `kanban/.slate-serve.json` and
  `kanban/.slate-serve.log` stay out of git (`.gitignore`). `python3 kanban/board.py doctor`
  checks the setup (merge driver, `.gitignore`, versions, SLATE.md) and the board; `setup`
  problems → `/slate:upgrade`, `tickets` problems → `/slate:sync`.
